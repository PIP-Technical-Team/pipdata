# Plan: Unified Environment Configuration (Revised)

Supersedes: `.cg-docs/plans/2026-04-28-env-setup.md`
Review findings incorporated from `/cg-plan-review` session (2026-04-30).

## Objective

Merge **all three** package-level environments (`.pipdata`, `.pipdataenv`,
`.logenv`) into a single `.pipdataenv` environment with namespaced keys. Add
accessor/reset helpers to replace raw `assign()`/`rm()`/`get()` calls.
Eliminate the redundant dual initialization in `aaa.R` + `zzz.R`.

## Context

The package currently has **3 package-level environments**:

| Environment | Defined in | Re-init in | Purpose | Active pipeline? |
|-------------|-----------|------------|---------|:---:|
| `.pipdata` | `aaa.R:2` | — | Stores `validation_report` (DLW validation accumulator) | **Yes** — Wrapper 2 (`pipdata_dlw_process`) |
| `.pipdataenv` | `aaa.R:6` | `zzz.R:20` | Stores `id_name` (save context), `survey_id` (process_data context) | **Yes** — Wrapper 3 (`pd_process_data`) |
| `.logenv` | `aaa.R:4` | `zzz.R:11` | Stores `survey_id` + error lists for deflation error handling | **No** — only `pd_deflation.R` (future pipeline step) |

**Problems addressed by this plan:**
1. `.pipdata` and `.pipdataenv` serve the same role (mutable package state) but are separate environments
2. `.logenv` is a third separate environment for the same purpose — no reason to keep it separate since the keys can be namespaced
3. Dual init of `.pipdataenv` in `aaa.R` + `zzz.R` is redundant
4. Raw `assign()`/`rm()`/`get()` scattered everywhere — no encapsulation

**Changes from original plan (2026-04-28):**
- `.logenv` is now **included** in scope (was deferred)
- New helper `pd_env_append()` for the repeated validation accumulation pattern
- `rlang` must be added to DESCRIPTION Imports (was missing)
- `pd_process_data.R` has 4 call sites, not 2
- `test-pipdata_validation_report.R` explicitly listed for update

## Key Namespacing Convention

All keys use a prefix to indicate origin:

| Prefix | Former environment | Example keys |
|--------|-------------------|--------------|
| `save_` | `.pipdataenv` | `save_id_name` |
| `process_` | `.pipdataenv` | `process_survey_id` |
| `validation_` | `.pipdata` | `validation_report` |
| `log_` | `.logenv` | `log_survey_id`, `log_piperr` |

### 1. Create accessor helpers

- **Requirements**: R4
- **Files**: `R/aaa.R` (modify)
- **Details**:
  Add 5 internal helpers below the `.pipdataenv` definition:
    ```r
    #' Set a value in the package environment
    #' @param key Character key name (use namespaced prefixes).
    #' @param value Value to store.
    #' @return `value` invisibly.
    #' @noRd
    pd_env_set <- function(key, value) {
      assign(key, value, envir = .pipdataenv)
      invisible(value)
    }

    #' Get a value from the package environment
    #' @param key Character key name.
    #' @param default Value to return if `key` does not exist (default: NULL).
    #' @return The stored value, or `default`.
    #' @noRd
    pd_env_get <- function(key, default = NULL) {
      if (rlang::env_has(.pipdataenv, key)) {
        return(get(key, envir = .pipdataenv))
      }
      default
    }

    #' Remove a key from the package environment
    #' @param key Character key name to remove.
    #' @return NULL invisibly.
    #' @noRd
    pd_env_rm <- function(key) {
      if (rlang::env_has(.pipdataenv, key)) {
        rm(list = key, envir = .pipdataenv)
      }
      invisible(NULL)
    }

    #' Reset the package environment (remove all keys)
    #' @return NULL invisibly.
    #' @noRd
    pd_env_reset <- function() {
      rm(list = ls(.pipdataenv), envir = .pipdataenv)
      invisible(NULL)
    }

    #' Append rows to a data.table stored in the package environment
    #'
    #' If the key doesn't exist yet, stores `new_rows` directly.
    #' If it exists, rbinds `new_rows` onto the existing value.
    #'
    #' @param key Character key name.
    #' @param new_rows A data.table to append.
    #' @return The updated value invisibly.
    #' @noRd
    pd_env_append <- function(key, new_rows) {
      existing <- pd_env_get(key)
      if (is.null(existing)) {
        pd_env_set(key, new_rows)
      } else {
        pd_env_set(key, rbind(existing, new_rows, ignore.attr = TRUE))
      }
    }
    ```
- **Tests**: New test file `tests/testthat/test-pd-env.R` with unit tests
  for all 5 helpers.
- **Acceptance criteria**: Helpers work correctly in isolation; tests pass.

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| `.pipdata$validation_report` is appended to across multiple function calls — reference semantics must be preserved | `pd_env_append()` handles accumulation via `rbind` — same semantics, encapsulated |
| `add_log()` uses dynamic `class` parameter as the `.logenv` key name — must preserve this pattern | Use `paste0("log_", class)` as the `.pipdataenv` key — dynamic naming preserved |
| `test-pipdata_validation_report.R` and `test-dlw_store_release.R` directly reference environments | Explicitly listed in Steps 4 and 5 with migration patterns |
| `rlang` not in Imports causes check failures | Step 0 adds it before anything else |
