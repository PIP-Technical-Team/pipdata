# Plan: Unified Environment Configuration

## Objective

Merge the two pipeline-active environments (`.pipdata`, `.pipdataenv`) into a
single `.pipdataenv` environment with namespaced keys. Add accessor/reset
helpers to replace raw `assign()`/`rm()`/`get()` calls. Eliminate the redundant
dual initialization of `.pipdataenv` in `aaa.R` + `zzz.R`.

`.logenv` is **intentionally excluded** from this plan — it is only consumed by
`pd_deflation.R` and its helpers (`piperr`, `add_log`, `log_failure`,
`get_ordered_level`), none of which are in the active pipeline call tree.
When deflation is integrated into the pipeline (roadmap: `position-deflation`),
`.logenv` should be migrated to the unified `.pipdataenv` at that time.

## Context

The package currently has **3 package-level environments**:

| Environment | Defined in | Re-init in | Purpose | Active pipeline? |
|-------------|-----------|------------|---------|:---:|
| `.pipdata` | `aaa.R:2` | — | Stores `validation_report` (DLW validation accumulator) | **Yes** — Wrapper 2 (`pipdata_dlw_process`) |
| `.pipdataenv` | `aaa.R:6` | `zzz.R:20` | Stores `id_name` (save context), `survey_id` (process_data context) | **Yes** — Wrapper 3 (`pd_process_data`) |
| `.logenv` | `aaa.R:4` | `zzz.R:11` | Stores `survey_id` + error lists for deflation error handling | **No** — only `pd_deflation.R` (future pipeline step) |

**Problems addressed by this plan:**
1. `.pipdata` and `.pipdataenv` serve the same role (mutable package state) but are separate environments
2. Dual init of `.pipdataenv` in `aaa.R` + `zzz.R` is redundant
3. Raw `assign()`/`rm()`/`get()` scattered everywhere — no encapsulation

## Implementation Steps

### 1. Create accessor helpers

- **Requirements**: R3
- **Files**: `R/aaa.R` (modify)
- **Details**:
  Add 4 internal helpers below the `.pipdataenv` definition. Keep `.logenv`
  and `.pipdata` definitions in place for now (`.pipdata` removed in Step 4;
  `.logenv` kept per R6):
    ```r
    #' @noRd
    pd_env_set <- function(key, value) {
      assign(key, value, envir = .pipdataenv)
      invisible(value)
    }

    #' @noRd
    pd_env_get <- function(key, default = NULL) {
      if (rlang::env_has(.pipdataenv, key)) {
        return(get(key, envir = .pipdataenv))
      }
      default
    }

    #' @noRd
    pd_env_rm <- function(key) {
      if (rlang::env_has(.pipdataenv, key)) {
        rm(list = key, envir = .pipdataenv)
      }
      invisible(NULL)
    }

    #' @noRd
    pd_env_reset <- function() {
      rm(list = ls(.pipdataenv), envir = .pipdataenv)
      invisible(NULL)
    }
    ```
- **Tests**: New test file `tests/testthat/test-pd-env.R` with unit tests for the 4 helpers.
- **Acceptance criteria**: Helpers work correctly in isolation.

### 2. Update `.onLoad` in `zzz.R`

- **Requirements**: R4, R6
- **Files**: `R/zzz.R` (modify)
- **Details**:
  - Remove the `.pipdataenv` re-creation block (lines 17–22).
  - **Keep** the `.logenv` re-creation block as-is (deferred per R6).

  - Optionally call `pd_env_reset()` to ensure clean `.pipdataenv` state on load.
- **Acceptance criteria**: `zzz.R` no longer re-creates `.pipdataenv`; `.logenv` block unchanged.

### 3. Migrate `.pipdataenv` consumers to use accessors

- **Requirements**: R2, R3
- **Files**: `R/save_pip.R`, `R/pd_process_data.R`
- **Details**:
  Replace raw `assign()`/`rm()`/`$` access with accessor helpers:

  | Old | New |
  |-----|-----|
  | `assign("id_name", id_name, envir = .pipdataenv)` | `pd_env_set("save_id_name", id_name)` |
  | `.pipdataenv$id_name` | `pd_env_get("save_id_name")` |
  | `rm(id_name, envir = .pipdataenv)` | `pd_env_rm("save_id_name")` |
  | `assign("survey_id", svy, envir = .pipdataenv)` | `pd_env_set("process_survey_id", svy)` |
  | `rm(survey_id, envir = .pipdataenv)` | `pd_env_rm("process_survey_id")` |

  **Call sites:**
  - `R/save_pip.R` — 3 references (lines 27, 32, 57)
  - `R/pd_process_data.R` — 2 references (lines 129, 134)
- **Acceptance criteria**: All raw `assign()`/`rm()` calls targeting `.pipdataenv` are replaced.

### 4. Migrate `.pipdata` consumers into `.pipdataenv`

- **Requirements**: R1, R2
- **Files**: `R/pipdata_dlw_validation.R`, `R/pipdata_validation_report.R`, `R/aaa.R`
- **Details**:
  Replace all `.pipdata` access with `.pipdataenv` via accessor helpers:

  | Old | New |
  |-----|-----|
  | `rlang::env_has(.pipdata, "validation_report")` | `!is.null(pd_env_get("validation_report"))` |
  | `rlang::env_poke(.pipdata, "validation_report", value)` | `pd_env_set("validation_report", value)` |
  | `.pipdata$validation_report` | `pd_env_get("validation_report")` |

  This pattern repeats **8 times** in `pipdata_dlw_validation.R` (once per
  validation function) and **3 times** in `pipdata_validation_report.R`.

  After all references are migrated, **remove** the `.pipdata` definition from
  `aaa.R`.
- **Acceptance criteria**: Zero references to `.pipdata` remain in `R/` files.

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| `.pipdata$validation_report` is appended to across multiple function calls — reference semantics must be preserved | `pd_env_set()`/`pd_env_get()` use the same underlying environment — reference semantics preserved by design |
| Some tests may reference `.pipdata` or `.pipdataenv` directly | Search test files for direct environment references and update accordingly |
| Future deflation integration needs `.logenv` migration too | Documented in plan scope and linked to roadmap `position-deflation` — `.logenv` left untouched for now |

## Out of Scope

- **`.logenv` migration** — deferred to when `pd_deflation()` is integrated into the pipeline (roadmap: `position-deflation`). At that point, `.logenv` consumers (`piperr`, `add_log`, `log_failure`, `get_ordered_level`) should migrate to `.pipdataenv` with `log_`-prefixed keys.
- Replacing `options("pipdata.verbose")` with an environment-based config (already works fine)
- Restructuring the `add_log()`/`piperr()` error-handling system itself (separate roadmap item: `logging-refactor`)
- Changing the DLW validation accumulation pattern to return values instead of side effects
